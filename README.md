# DivyaBharat

An AI-powered Indian spiritual and heritage travel companion. DivyaBharat helps travelers discover temples, forts, caves, ghats, ashrams and other heritage sites across India: with rich historical context, an AI guide, a full trip planner, an interactive globe, and a personal pilgrimage journal.

---

## Features

- **Explore Places** - Browse and search 6000+ real heritage sites across India with category, region, and full-text search filters
- **Interactive Map** - View all places on a live map of India with category filtering and marker clustering
- **AI Guide** - Ask anything about a place and get knowledgeable answers powered by Groq and Llama 3.3, enriched with Wikipedia context
- **Smart Caching** - AI responses are cached in the database so repeated questions return instantly
- **AI Trip Planner** - Describe your journey and get a complete day-by-day itinerary generated by AI, with stops plotted on a live route map
- **My Trips** - Create, manage, and view all your planned trips; add or reorder stops; see the full route drawn on a Leaflet map
- **Smriti · Chronicles** - A personal pilgrimage journal. Write entries about sacred places you have visited, tag a location and date, and optionally link entries to a trip. Entries are presented on a chronological timeline with alternating left-right layout
- **My Places** - Personal profile page showing all visited places with visit overlays and visit date tracking
- **Place Submission** - Logged-in users can submit new heritage places with a map picker for coordinates
- **Admin Panel** - Admins can approve or reject submissions and trigger Wikidata imports
- **Authentication** - Register and login with email/password or Google account; session persists across refreshes
- **Role System** - User and admin roles with protected routes and server-side middleware
- **Wikidata Sync** - Automated daily import of Indian heritage sites from Wikidata with deduplication

## Homepage

The homepage is built as a series of full-screen portal sections that switch on scroll, each with a Ken Burns image, directional gradient veil, and animated text reveals.

- **Hero portal**: Full-screen ghat/aarti image with the DivyaBharat title, description and two CTAs
- **Feature portals**: Three subsequent portals introducing the AI Guide, Sacred Map and Yatra Planner
- **Globe discovery section**: An interactive `globe.gl` globe renders all places with coordinates as gold dots on a dark night-earth sphere. The globe auto-rotates; hovering a dot freezes rotation and shows a full-bleed place card beside it. Drag to spin manually; rotation resumes 3 seconds after release
- **Browse by Type**: Horizontally scrollable pill ribbon for all 12 place categories
- **Chronicles CTA**: Split layout with a 3D-tilted animated journal card on the right that loops a typewriter-effect sample entry when scrolled into view
- **Submit a Place CTA**: Community contribution prompt

## Database Schema

### users

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| name | STRING | Required |
| email | STRING | Unique |
| password | STRING | Nullable for Google OAuth users |
| role | ENUM | user, admin - default is user |
| google_id | STRING | Nullable, populated on Google login |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

### places

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| name | STRING | Required |
| description | TEXT | - |
| history | TEXT | - |
| category | ENUM | temple, fort, cave, ghat, ashram, gurudwara, sacred_river, ancient_site, heritage_village, museum, natural_sacred, other |
| state | STRING | Required |
| city | STRING | - |
| latitude | DECIMAL(10,8) | Float getter applied |
| longitude | DECIMAL(11,8) | Float getter applied |
| image_url | STRING | Wikimedia Commons thumbnail URL where available |
| status | ENUM | pending, approved, rejected - default is pending |
| submitted_by | UUID | FK to users.id |
| wikidata_id | STRING | Unique, populated for Wikidata-sourced places |
| source | ENUM | wikidata, community - default is community |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

Places use a default scope that filters to approved status only. Admin queries use `Place.unscoped()` to bypass this. Community submissions are never overwritten by Wikidata sync.

### trips

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| user_id | UUID | FK to users.id |
| name | STRING | Required |
| description | TEXT | - |
| total_days | INTEGER | - |
| start_date | DATEONLY | Optional |
| end_date | DATEONLY | Optional |
| is_public | BOOLEAN | Default false |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

### trip_places

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| trip_id | UUID | FK to trips.id |
| place_id | UUID | FK to places.id, nullable (custom stops not in DB are allowed) |
| destination_name | STRING | Required |
| destination_city | STRING | - |
| destination_state | STRING | - |
| latitude | DECIMAL(10,8) | Float getter applied |
| longitude | DECIMAL(11,8) | Float getter applied |
| day_number | INTEGER | Which day of the trip |
| order | INTEGER | Order within the day |
| duration_hours | DECIMAL(4,1) | Estimated visit duration |
| visit_date | DATEONLY | Optional |
| notes | TEXT | - |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

### journal_entries

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| user_id | UUID | FK to users.id |
| title | STRING(255) | Required |
| content | TEXT | Required |
| location_name | STRING(255) | Optional: name of the place visited |
| visit_date | DATEONLY | Optional |
| trip_id | UUID | FK to trips.id, nullable: link entry to a trip |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

### ai_guide_cache

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| place_id | UUID | FK to places.id, cascades on delete |
| question_hash | STRING(32) | MD5 hash of normalized question |
| question | TEXT | Original question text |
| answer | TEXT | AI response |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

Unique index on (place_id, question_hash) prevents duplicate cache entries.

### user_places

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| user_id | UUID | FK to users.id, cascades on delete |
| place_id | UUID | FK to places.id, cascades on delete |
| visited_at | DATE | Auto |
| created_at | DATE | Auto |
| updated_at | DATE | Auto |

Unique index on (user_id, place_id) prevents duplicate entries.

## Getting Started

### Prerequisites

- Node.js v18+
- PostgreSQL 14+ (for local development)
- Docker and docker-compose (for containerized setup)
- Groq API key - free at [console.groq.com](https://console.groq.com)
- Google OAuth credentials - from [console.cloud.google.com](https://console.cloud.google.com)

---

### Option 1 - Local Development

**1. Clone the repository**

```bash
git clone https://github.com/gorejuee/DivyaBharat.git
cd DivyaBharat
```

**2. Setup the backend**

```bash
cd divyabharat-backend
npm install
```

Create a `.env` file inside `divyabharat-backend/`:

```
PORT=3000
DB_NAME=divyabharat_db
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_HOST=localhost
JWT_SECRET=your_jwt_secret
GROQ_API_KEY=your_groq_api_key
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GOOGLE_CALLBACK_URL=http://localhost:3000/api/auth/google/callback
```

Create the database:

```sql
CREATE DATABASE divyabharat_db;
CREATE USER your_db_user WITH PASSWORD 'your_db_password';
GRANT ALL PRIVILEGES ON DATABASE divyabharat_db TO your_db_user;
```

Run migrations and seed data:

```bash
npx sequelize-cli db:migrate
npx sequelize-cli db:seed:all
```

Start the backend:

```bash
npm run dev
```

**3. Setup the frontend**

```bash
cd divyabharat-frontend
npm install
npm run dev
```

App runs at `http://localhost:5173`, backend at `http://localhost:3000`

**4. Import heritage places (requires internet, run once on first setup)**

Login as admin and click "Import from Wikidata" in the admin panel, or:

```bash
curl -X POST http://localhost:3000/api/admin/import-wikidata \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN"
```

### Option 2 - Docker

Docker handles the backend and database together. You still run the frontend locally.

**1. Clone the repository**

```bash
git clone https://github.com/gorejuee/DivyaBharat.git
cd DivyaBharat
```

**2. Create a `.env` file in the root `DivyaBharat/` folder**

```
DB_PASSWORD=your_db_password
JWT_SECRET=your_jwt_secret
GROQ_API_KEY=your_groq_api_key
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
```

**3. Start the backend and database**

```bash
docker-compose up --build
```

**4. Run migrations and seed data**

```bash
docker exec -it divyabharat_backend npx sequelize-cli db:migrate
docker exec -it divyabharat_backend npx sequelize-cli db:seed:all
```

**5. Start the frontend**

```bash
cd divyabharat-frontend
npm install
npm run dev
```

App runs at `http://localhost:5173`

To stop:

```bash
docker-compose down
```
